# Interactive lesson packages — format, player, task type (proposal)

Status: **proposal 2026-08-21** (Patrick + agent session) · Resolves the open question in `ANIMATIONS.md` §4 and the High-priority "Animation / explainer player" row in `TOOLS.md` §6A.  
Scope: **K–4 first** (animation-heavy, tap/drag interactive), format designed to serve K–12.  
Exemplar: [`subjects/science/lessons/lesson.science.k2.living.01.md`](./subjects/science/lessons/lesson.science.k2.living.01.md) + package `assets/lessons/lesson.science.k2.living.01/`.

---

## 1. Why this exists

The K–12 tracker (Google Sheet, built 2026-08-18) shows **~125 pure `gap` rows in K–4**, almost all science and history. The brief for that band is *animation-heavy and interactive*. Today nothing on the Goji computer can play such a lesson: School Day tasks are `pdf | book | journal | quiz | app_time`, and the parent catalog knows only those. Authoring 125 animated lessons with no surface to launch them would produce orphan media — exactly what `ANIMATIONS.md` §1 forbids.

So one engineering decision unblocks the whole K–4 backlog: **a lesson package format + a Pi-side lesson player + one new `content` task subject_type.**

## 2. Decision (proposed)

| Question | Answer | Why |
|----------|--------|-----|
| On-device format | **Self-contained HTML** (one `index.html`, inline CSS/JS, inline SVG, plus an optional generated `media/` folder of stills, short muted MP4 clips and MP3 narration; no network, no external libs) | Pi-cheap (short 720p clips decode fine on a Pi 4/5; everything degrades to SVG + browser speech if media is absent), tiny on SD, crisp at any kiosk resolution, honours `prefers-reduced-motion`, trivially authored/edited by agents, already proven by the `my-apps` HTML path |
| Authoring | Agents write HTML directly from the lesson plan + animation brief; **art/clips/narration generated by Grok Imagine + Grok TTS from `assets.json`** (`tools/lesson_assets/`); Claude Design stays an *optional* source | Removes the export-conversion step that stalled `ANIMATIONS.md` §4; one style preset keeps K–4 consistent |
| Manifest | `lesson.json` beside `index.html` (§3) | IDs are law — the manifest is what the catalog and parent app read |
| Player | New kiosk component `LessonPlayer.svelte` (hub app id **`lessons`**) rendering the package in a sandboxed `<iframe srcdoc>` and listening for `postMessage` events (§4) | Same mechanism `MyApps` already uses for user HTML apps; no new runtime |
| Parent assignment | New `content` task `subject_type: "lesson"` (§5) | One additive row in `SYNC_API.md`; verify dialect unchanged |
| Proof | `lesson.completed` activity event with check score (§5) | Every lesson terminates in a measurable gate (PRACTICES §1) |
| Ship path | Packages seeded in `goji_computer/backend/seed_data/lessons/` on the image; later deltas via catalog sync (`catalog_lessons`) | Offline-first; image carries the curriculum |

Video (WebM/MP4) and Lottie are **not** ruled out for later; they can be embedded *inside* a package if a lesson truly needs them. The package boundary stays the same.

## 3. Package layout + manifest

```
assets/lessons/<lesson.id>/
  lesson.json      # manifest (below)
  index.html       # the lesson — self-contained
  preview.png      # optional, 16:9, for parent app picker
  assets.json      # generation manifest (prompts, clips, voice lines) — tools/lesson_assets/
  media/           # generated art/clips/narration — gitignored, shipped with the image
```

**Art, clips and voice** are generated once at authoring time with Grok Imagine (image + image-to-video) and Grok TTS via `tools/lesson_assets/gen_assets.py` from the package's `assets.json`, under one shared storybook-watercolor preset (`tools/lesson_assets/style.json`). The HTML loads `media/index.js` and falls back to inline SVG/emoji/browser speech for anything not generated, so a package always runs. ≈ $3–6 per lesson. See [`tools/lesson_assets/README.md`](./tools/lesson_assets/README.md).

`lesson.json`:

```json
{
  "id": "lesson.science.k2.living.01",
  "title": "Living or not living?",
  "subject": "science",
  "band": "k2",
  "grade_hint": "K",
  "objectives": ["obj.science.k2.living.01"],
  "va_sol": ["K.6"],
  "duration_min": 12,
  "anchor": { "book": "aesop-fables", "note": "animal of the week = specimen" },
  "stages": ["hook", "teach", "practice", "check"],
  "check": { "quiz_id": "quiz.science.k2.living.01", "n_items": 5, "pass": 4 },
  "animations": ["anim.science.k2.living.01"],
  "reduced_motion": true,
  "version": 1,
  "entry": "index.html"
}
```

Rules: `id` equals the folder name and the lesson-plan ID; every `obj.`/`quiz.`/`anim.` ID must resolve in `curriculum/` (audit checklist §4); `pass` is the gate the parent app uses for standing.

## 4. Player contract (package ⇄ kiosk)

The package runs inside the kiosk's `LessonPlayer` iframe and talks only via `window.parent.postMessage`. Nothing else — no fetch, no storage. Messages (`type` field):

| From package | Payload | Player does |
|--------------|---------|-------------|
| `lesson.ready` | `{ id, version }` | start timer, show chrome |
| `lesson.stage` | `{ stage }` | progress dots; optional analytics |
| `lesson.check` | `{ quiz_id, score, total, items:[{id, correct, chosen}] }` | persist attempt locally |
| `lesson.complete` | `{ score, total, duration_s }` | write `lesson.completed` event, close with Goji "done" chrome, mark School Day task |

| From player | Payload | Package does |
|-------------|---------|--------------|
| `player.config` | `{ reduced_motion, child_name?, lang }` | respect motion pref; personalise greeting |

The package also works stand-alone in any browser (no parent → messages are no-ops), which is how authors and parents preview it.

Exit/skip is always available in the player chrome (kid never trapped). Replay of the teach stage is a package-level button (brief bar: "skippable, replayable").

## 5. Sync contract additions (to land in `goji_cloud/SYNC_API.md` first — rule 1)

**Plan task — kind `content`:**

```json
{ "subject_type": "lesson", "lesson_id": "lesson.science.k2.living.01", "min_score": 4 }
```

Completion: device marks the task `done` with `completed_how: "lesson_check"` when a `lesson.complete` arrives with `score >= min_score`; otherwise the task stays open and the child may replay. Older Pis that don't know `lesson` ignore the task (additive).

**Activity event `lesson.completed`** (point event):

- `app`: `lessons`
- `subject_type`: `lesson`
- `subject_id`: the lesson id
- `payload`: `{ "quiz_id", "score", "total", "objectives": [...], "attempt": <int> }`
- `duration_s`: time from `lesson.ready` to `lesson.complete`

Retakes produce multiple events; dashboard shows latest by `occurred_at` (same rule as `quiz.submitted`).

**Catalog:** `catalog_lessons` (id, title, subject, band, objectives, va_sol, duration_min, version) generated from the `lesson.json` files — the parent wizard's picker and `catalog_v1.json` standing map read it. `kind` for the wizard slot: `lesson`.

## 6. Authoring bar for a K–4 package (house style, on top of PRACTICES §3)

1. **Four stages, always**: Hook (≤ 20 s, a question) → Teach (≤ 90 s, animated, narrated by on-screen text + optional voice) → Practice (≥ 6 interactions: tap / drag / sort; instant feedback; misconception-aware) → Check (3–5 items, diagnostic distractors, score posted).
2. **Touch-first**: targets ≥ 64 px; no hover-only affordances; big type (K–2 ≥ 28 px body).
3. **Read-aloud for pre-readers**: K–1 every instruction has a speaker button (Web Speech API when present; graceful if absent — text stays).
4. **Calm motion**: brand rules from `ANIMATIONS.md` §3 — no confetti cascades, seal/red-cream chrome, `prefers-reduced-motion` swaps animation for stepped stills.
5. **Anchor-tied**: K–2 science/history pull the specimen or setting from the current Aesop fable; research hand-off named in the lesson plan.
6. **One objective per package** (K–5).
7. **Self-contained**: no CDN, no fonts beyond system stack; HTML < 300 KB, generated `media/` ≲ 12 MB per lesson (five 6 s clips at 720p plus stills and narration).

| Grade 2 US History | 13 | story-map + timeline drag | |
| Grade 4 Virginia Studies | 13 | map + timeline + primary-source tap | |
| Grade 1 / 3 History | 7 + 10 | same families | |
| Grades 1–4 Science | 7 each | observe-and-sort, cycle animation (life/water), cause-effect | |
| K–4 Math gaps | 4–8 each | principle animation + manipulative practice (complements drills) | Math modules remain the practice surface |

Each lesson authored = objective row + lesson plan + quiz blueprint + package + INDEX row + `skills/` status flip + tracker row filled (Objective ID, Lesson ID, Teach media). That is the unit of work; ~125 units.
